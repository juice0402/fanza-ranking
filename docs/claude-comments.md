# Claude によるコメント作り（毎日の予約タスク）

毎日 22:40（日本時間）の自動更新では、Gemini の無料枠（1日20回ほど）の都合で、AIコメントが付かない作品が出ます。
そうした作品は定型文（`comment_kind: template`）のまま保存されます。
それを、**毎日 23:20（日本時間）に Claude の予約タスクが書き直す**ための手順書です（予約タスクはこの手順書どおりに動きます）。

```
22:40  GitHub Actions（get_new_releases.py）… 新作を取得 → Gemini でコメント → 付かなかった作品は定型文
23:20  Claude の予約タスク … 定型文の作品に、Claude がコメントを書く → PR → CIが緑ならMerge → 公開
```

Claude が書いたコメントは `comment_kind: "ai"` にします（画面の「コメントの一部はAIが自動で作成」の注記の対象。Gemini と区別はしません）。
すでに `ai` の作品（Gemini が書いたもの）は上書きしません。

予約タスクの名前は「毎日のAIコメント書き足し（Claude）」です（実行は自動承認の設定）。夜の23:20にしているのは、運営者が朝5時から使うとき、Claudeの利用枠（5時間ごとにリセット）が回復しているようにするためです（予約タスクもふだんのチャットと同じ利用枠を使う）。止める・時間を変える・手順を変えるときは、Claudeに頼んでください（手順そのものは、予約タスクが毎回このファイルを読むので、このファイルを直せば反映されます）。
2026-10-03 のテスト実行で、PRの作成 → CI → Merge → 本番での表示まで通ることを確認しています（PR #6）。

## 手順

1. リポジトリ `juice0402/fanza-ranking` を使える状態にする（無ければ add_repo → clone）。`main` を最新にして、作業用のブランチを作る
   `git fetch origin main && git checkout -B claude/comments-YYYYMMDD origin/main`
2. 対象を出す: `python3 scripts/claude_comments.py list --limit 40`
   - `total_pending` が 0 なら、**何も変更せず、PRも作らずに終了**（「対象なし」と報告）
   - 出力には作品タイトルを含めません（出演者・メーカー・形式・発売日だけ）。形式は VR / 8K のような英数字のタグだけで、日本語のタグ（作品の内容を表す言葉が混ざることがある）は出ません
3. 下の「書き方」に沿って、作品ごとにコメントを書き、`{"cid": "コメント", ...}` のJSONファイルにする（作業用の置き場に。リポジトリには入れない）
4. 点検して書き込む: `python3 scripts/claude_comments.py apply ファイル.json`
   - 先に `--dry-run` で点検してもよい。問題があると**何も書き込まれず**、理由が出る。直してもう一度実行する
5. `bash scripts/check.sh` を実行して全部成功することを確認する
6. `git status` で、変わったのが **`site/src/data/new_releases.json` だけ**であることを確認する。他のファイルが変わっていたらコミットしない
7. コミット → ブランチをpush → PRを作る（`gh api repos/juice0402/fanza-ranking/pulls`。CLAUDE.md の守ること1・2）
   - コミットメッセージ: `AIコメントを追加（Claude）: N件`
8. CIが終わるまで待つ（`gh api repos/juice0402/fanza-ranking/commits/<ブランチの先頭>/check-runs` で `conclusion` を見る。数分）
   - **緑ならMerge**（`gh api -X PUT repos/juice0402/fanza-ranking/pulls/<番号>/merge -f merge_method=merge -f sha=<先頭>`）
   - 赤・時間切れ・衝突（Mergeできない）のときは**Mergeしない**。PRを開いたまま、理由を報告して終了する。衝突のときは、ブランチを捨てて手順1からやり直してよい（1回だけ）
9. 最後に報告する: 何件書いたか／PR番号／CIの結果／Mergeしたか／残りの定型文の件数

Mergeしてよいのは、**このコメント更新のPR（データファイルだけを変えるもの）で、CIが緑のとき**だけです（運営者の許可済み）。

## 書き方

Gemini に渡しているルール（`get_new_releases.py` の `build_prompt`）と同じ考え方です。

- 60〜90文字の、短い紹介コメントを日本語で（40〜120文字まで受け付ける）
- 上品で、読んだ人が気になる前向きなトーン。「です・ます」調
- 使ってよい情報は、**出演者・メーカー・形式（VR / 8K など）・発売日（または予約中であること）だけ**
- 作品の中身（ストーリー・内容・演出）は断定しない。出演者の経歴や容姿など、確かめられないことも書かない。分からないことは書かない
- 過激・直接的な表現、性的な描写は使わない。未成年を連想させる言葉も使わない
- 出演者名は入れてよい（1回まで。複数人のときは「〇〇さんほか」でもよい）。メーカーが `null` のときは触れない
- 挨拶・前置き・絵文字・飾りの記号・マークダウンは入れず、コメント本文だけ
- **書き出しと言い回しを作品ごとに変える**。同じ文を使い回さない（使い回すと `apply` が断る）
- 発売済みなら「発売中」「新作」、予約なら「発売前」「予約受付中」の気持ちで。日付を入れてもよい

書き方の例（名前は仮のもの）:

- 〇〇さん出演の、△△が贈るVR作品。発売日は10月3日です。臨場感のある映像で味わえる一本として、気になる方は早めにチェックしてみてください。
- 予約受付中の新作です。△△の一本で、〇〇さんが出演しています。11月22日の発売に向けて、いまのうちに目を通しておきたい作品です。

## うまくいかないとき

- `apply` が断ったとき: 表示された理由（文字数・使えない言葉・同じ文の使い回し など）を直して、もう一度実行する
- CIが赤いとき: Mergeせず、PRを開いたまま報告する（運営者がClaudeに相談する）
- リポジトリに入れない／PRを作れないとき: 無理に回り道をせず、できなかった理由を報告して終了する（データは壊れていないので、次の日にもう一度やればよい）
- 1日抜けても大丈夫: 次の日の実行が、残りの定型文もまとめて書き直す
