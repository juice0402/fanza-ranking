# Claude による月のまとめ記事（毎月1日の予約タスク）

毎月1日 1:25（日本時間）に、Claude の予約タスクが、**前の月に発売された作品のうち、当サイトで紹介した作品のまとめ記事**を1本書きます（2026-10-07 から。運営者の希望「月のまとめ記事」）。
記事は、月のページ `/month/<YYYY-MM>/`（例: `/month/2026-10/`）の**いちばん上**に出ます。検索で「FANZA 新作 2026年10月」のような言葉から来てもらうための、サイトの読みものです。

```
 0:05  GitHub Actions … 新作を取得
 0:20  Claude の予約タスク（毎日）… コメントを書く
 0:50  Claude の予約タスク（毎週月曜）… 週のまとめ記事
 1:25  Claude の予約タスク（毎月1日）… 前の月のまとめ記事を書く → PR → CIが緑ならMerge → 公開
```

記事の中身は3つです（週のまとめ記事 `docs/claude-roundups.md` と同じ形・同じ点検）。

- **導入文（lead）**: その月を一言でまとめる文章（100〜360文字）
- **この月の傾向（trend）**: 前の月との比べ・ジャンルの増減・新着の人気順で上位に入った作品から読み取れること（80〜360文字）
- **注目の作品（picks）とそのひとこと（note）**: 4〜8本。ひとことは40〜120文字

傾向の表（本数と前の月との増減・ジャンルの横棒・人気順の上位の作品）は、`apply` が**書いたときの数字を記事と一緒に保存し**（`facts`）、サイトはその数字を表にします。
月の作品が30本に満たない月は、記事を作りません（内容が薄くなるため）。

予約タスクの名前は「毎月のまとめ記事（Claude）」です。止める・時間を変える・手順を変えるときは、Claudeに頼んでください（予約タスクが毎回このファイルを読むので、このファイルを直せば反映されます）。

## 手順

1. リポジトリ `juice0402/fanza-ranking` を使える状態にする（無ければ add_repo → clone）。`main` を最新にして、作業用のブランチを作る
   `git fetch origin main && git checkout -B claude/monthly-$(TZ=Asia/Tokyo date +%Y%m%d-%H%M) origin/main`
2. 対象を出す: `python3 scripts/claude_monthly.py list`
   - `status` が `ready` 以外（`not_finished`・`already_written`・`too_few_items`）なら、**何も変更せず、PRも作らずに終了**（理由を報告）
   - 出力には作品タイトルを含めません（出演者・メーカー・形式・発売日・収録時間・ジャンル（サイトのジャンルのページの一覧にあるものだけ）・デビュー作か・新着の人気順の最高順位だけ）
   - 月の集計: `total`・`per_week`（週＝月曜はじまりごとの本数）・`busy_days`（掲載の多かった日、3日）・`makers`・`actresses`（2本以上）・`formats`・`weekly`（この月の週のまとめ記事の週）
   - `trend` に傾向の数字: `total`・`prev_total`（前の月の本数）・`vr`・`prev_vr`・`debut`・`genres`（`count` と前の月の `prev`）・`popular`（この月に発売された作品の、新着の人気順の最高順位 `best`・その日 `best_date`・10位以内の日数 `days10`・100位以内の日数 `days100`・メーカー・出演者。過去作品の作品も入る）・`popular_ranked`・`popular_makers`
3. 下の「書き方」に沿って記事を書き、次の形のJSONファイルにする（作業用の置き場に。リポジトリには入れない）
   ```json
   {"month": "listに出た月（YYYY-MM）", "lead": "導入文", "trend": "この月の傾向", "picks": [{"cid": "作品ID", "note": "ひとこと"}]}
   ```
4. 点検して書き込む: `python3 scripts/claude_monthly.py apply ファイル.json`（先に `--dry-run` で点検してもよい。問題があると**何も書き込まれず**、理由が出る）
5. `bash scripts/check.sh` を実行して全部成功することを確認する
6. `git status` で、変わったのが **`site/src/data/monthly.json` だけ**であることを確認する。他のファイルが変わっていたらコミットしない
7. コミット → ブランチをpush → PRを作る（`gh api repos/juice0402/fanza-ranking/pulls`。CLAUDE.md の守ること1・2）
   - コミットメッセージ: `月のまとめ記事を追加（Claude）: 2026年10月`
8. CIが終わるまで待つ（`gh api repos/juice0402/fanza-ranking/commits/<ブランチの先頭>/check-runs` で `conclusion` を見る）
   - **緑ならMerge**（`gh api -X PUT repos/juice0402/fanza-ranking/pulls/<番号>/merge -f merge_method=merge -f sha=<先頭>`）
   - 赤・時間切れ・衝突のときは**Mergeしない**。PRを開いたまま、理由を報告して終了する。衝突のときは、ブランチを捨てて手順1からやり直してよい（1回だけ）
9. Merge したら、数分待って本番の `https://fanza-ranking.pages.dev/month/<YYYY-MM>/?cb=日時` を WebFetch で見て、記事が出ているかを確認する。見られなかったら「未確認」と書く
10. 最後に報告する: どの月の記事か／PR番号／CIの結果／Mergeしたか／本番で確認できたか

Mergeしてよいのは、**この月のまとめ記事のPR（`monthly.json` だけを変えるもの）で、CIが緑のとき**だけです（CLAUDE.md の守ること1）。

## 書き方

週のまとめ記事（`docs/claude-roundups.md` の「書き方」）と同じです。`apply` が同じ点検をします。ちがうのは次の点だけ。

- 期間は「2026年10月」「10月1日から10月31日」のように書く。**「今月」「先月」「今週」など、日がたつと古くなる言い方は使わない**（`apply` が断る）
- 導入文（lead）: この月に当サイトで紹介した本数、掲載の多かった週・日、メーカーや出演者の目立った動き（本数）、VR・8K などの形式を事実で書く。本数は「当サイトで紹介した◯本」「掲載した◯本」と書く（FANZA全体の発売本数ではない）。人気順のことは傾向に書く
- この月の傾向（trend）: `trend` の数字から読み取れることを、数字を添えて書く（前の月との本数の比べ・ジャンルの増減・VR作品の割合・デビュー作・新着の人気順で上位に入った作品の傾向）。理由の推測・確かめられない評価（「話題」「大人気」「待望」「圧倒的」など）は書かない。前の月の作品が無い（`prev_total` が 0）ときは、比べずに、その月の数字だけで書く
- 注目の作品（picks）: 4〜8本。この月に発売された作品（`items` の `cid`）だけ。`no_pick: true` の作品は選ばない（`apply` が断る）。週ごと・メーカーごとにばらけるように選ぶ。新着の人気順の最高順位（`best_rank`）・デビュー作（`debut`）も選ぶ目安にしてよい（サイトが札を付ける）
- 使ってよい数字は、`list` に出た数字（本数・日付・収録時間・順位・日数）と、その月の日付（1〜31日）・年・月・前の月だけ

書き方の例（名前・数字は仮のもの）:

- lead: 2026年10月に発売された新作のうち、当サイトで紹介したのは132本でした。掲載が多かったのは9月28日からの週で、10月3日には43本が並んでいます。メーカーでは〇〇が8本、△△が7本と続き、VR作品も29本ありました。
- trend: 前の月の98本から34本増えて、132本を掲載しました。ジャンルでは巨乳が44本と最も多く、前の月から12本増えています。新着の人気順では、〇〇の作品が10月5日に最高1位まで上がり、10位以内に3日入りました。上位10本のうち4本が〇〇の作品です。

## うまくいかないとき

- `apply` が断ったとき: 表示された理由（文字数・使えない言葉・一覧にない数字・同じ文の使い回し など）を直して、もう一度実行する
- `list` の `status` が `ready` でないとき: 何もしないで終了する（記事がない月があっても、サイトは壊れない。月のページは、記事なしで今までどおり出る）
- CIが赤いとき: Mergeせず、PRを開いたまま報告する
- 抜けた月の記事は、あとから `list --month YYYY-MM` で書ける（1回の実行で1本）
