# Claude による週のまとめ記事（毎週月曜の予約タスク）

毎週月曜 0:50（日本時間）に、Claude の予約タスクが、**前の週（月曜〜日曜）に発売された作品のまとめ記事**を1本書きます。
公開先は `/weekly/<週の月曜日>/`（例: `/weekly/2026-09-28/`）。検索で「FANZA 新作 10月第1週」のような言葉から来てもらうための、サイトの読みものです。

```
 0:05  GitHub Actions … 新作を取得（月曜の新作もここで入る）
 0:20  Claude の予約タスク（毎日）… 定型文の作品にコメントを書く
 0:50  Claude の予約タスク（毎週月曜）… 前の週のまとめ記事を書く → PR → CIが緑ならMerge → 公開
```

記事の中身は2つだけです。

- **導入文（lead）**: その週を一言でまとめる文章（80〜300文字）
- **注目の作品（picks）とそのひとこと（note）**: 3〜6本。ひとことは40〜120文字

本数・日別・メーカー別・出演者別・形式別の表は、**サイトが作品データから自動で数えて表示します**（記事のファイルには入れません。Claude が数字を書き間違えても、表は正しいまま）。
週の作品が10本に満たない週は、記事を作りません（内容が薄くなるため）。

予約タスクの名前は「毎週のまとめ記事（Claude）」です（自動承認の設定）。止める・時間を変える・手順を変えるときは、Claudeに頼んでください（手順そのものは、予約タスクが毎回このファイルを読むので、このファイルを直せば反映されます）。

## 手順

1. リポジトリ `juice0402/fanza-ranking` を使える状態にする（無ければ add_repo → clone）。`main` を最新にして、作業用のブランチを作る
   `git fetch origin main && git checkout -B claude/roundup-YYYYMMDD origin/main`
2. 対象を出す: `python3 scripts/claude_roundups.py list`
   - `status` が `ready` 以外（`not_finished`・`already_written`・`too_few_items`）なら、**何も変更せず、PRも作らずに終了**（理由を報告）
   - 出力には作品タイトルを含めません（出演者・メーカー・形式・発売日・収録時間だけ）。週の集計（本数・日別・メーカー・出演者・形式）も出ます
3. 下の「書き方」に沿って、記事を書き、次の形のJSONファイルにする（作業用の置き場に。リポジトリには入れない）
   ```json
   {"week_start": "listに出た週の月曜日", "lead": "導入文", "picks": [{"cid": "作品ID", "note": "ひとこと"}]}
   ```
4. 点検して書き込む: `python3 scripts/claude_roundups.py apply ファイル.json`
   - 先に `--dry-run` で点検してもよい。問題があると**何も書き込まれず**、理由が出る。直してもう一度実行する
5. `bash scripts/check.sh` を実行して全部成功することを確認する
6. `git status` で、変わったのが **`site/src/data/roundups.json` だけ**であることを確認する。他のファイルが変わっていたらコミットしない
7. コミット → ブランチをpush → PRを作る（`gh api repos/juice0402/fanza-ranking/pulls`。CLAUDE.md の守ること1・2）
   - コミットメッセージ: `週のまとめ記事を追加（Claude）: 2026年9月28日〜10月4日`
8. CIが終わるまで待つ（`gh api repos/juice0402/fanza-ranking/commits/<ブランチの先頭>/check-runs` で `conclusion` を見る。数分）
   - **緑ならMerge**（`gh api -X PUT repos/juice0402/fanza-ranking/pulls/<番号>/merge -f merge_method=merge -f sha=<先頭>`）
   - 赤・時間切れ・衝突（Mergeできない）のときは**Mergeしない**。PRを開いたまま、理由を報告して終了する。衝突のときは、ブランチを捨てて手順1からやり直してよい（1回だけ）
9. Merge したら、数分待って本番の `https://fanza-ranking.pages.dev/weekly/<週の月曜日>/?cb=日時` を WebFetch で見て、記事が出ているかを確認する（`?cb=` を付けないと古い内容が返ることがある）。見られなかったら「未確認」と書く
10. 最後に報告する: どの週の記事か／PR番号／CIの結果／Mergeしたか／本番で確認できたか

Mergeしてよいのは、**このまとめ記事のPR（`roundups.json` だけを変えるもの）で、CIが緑のとき**だけです（運営者の包括的な許可にもとづく。CLAUDE.md の守ること1）。

## 書き方

コメントの書き方（`docs/claude-comments.md`）と同じ考え方です。`apply` が点検するので、違反するとはじかれます。

使ってよい情報は、**`list` に出たもの（出演者・メーカー・形式・発売日・収録時間・週の集計）だけ**です。作品タイトルは見えません（見ないで書きます）。

### 導入文（lead）

- 80〜300文字。「です・ます」調で、読んだ人がこの週の新作を見てみたくなる、前向きなトーン
- その週に何本発売されたか、どの日に多かったか、メーカーや出演者の目立った動き（本数）、VR・8K などの形式があったこと、を事実で書く
- 数字は、`list` に出た数字（本数・日付・収録時間）だけを使う（ほかの数字が入ると `apply` が断る）
- 期間は日付で書く（例: 「9月28日から10月4日に」）。**「今週」「先週」「今日」など、日がたつと古くなる言い方は使わない**（記事は残り続けるため。使うと `apply` が断る）
- 作品の中身（ストーリー・内容・演出）、出演者の経歴・容姿・人気の評価、ランキングのような言い方（「No.1」「人気」）は書かない（確かめられないため）
- 過激・直接的な表現、性的な描写、未成年を連想させる言葉は使わない
- 挨拶・絵文字・飾りの記号・マークダウン・URLは入れず、本文だけ。改行も入れない

### 注目の作品（picks）とひとこと（note）

- 3〜6本。**この週に発売された作品の `cid` だけ**。同じ作品を2回入れない
- 選び方の目安（すべて `list` の事実から）: 発売日がばらける・メーカーがばらける・VR や 8K などの形式がある・収録時間が分かる・出演者の名前がある。タイトルや内容で選ばない
- ひとことは40〜120文字。その作品の `list` の情報（出演者・メーカー・形式・発売日・収録時間）だけで、1本ごとに書き出しと言い回しを変える。同じ文を使い回さない
- 出演者名は入れてよい（1回まで）。収録時間は「約120分」のように事実だけ。「長い」「短い」などの評価はしない
- 上の導入文と同じ、使えない言葉・言い方のルールがそのまま当てはまる

書き方の例（名前・数字は仮のもの）:

- lead: 9月28日から10月4日に発売された新作は、全部で24本でした。発売が多かったのは10月3日で、6本が並びました。メーカーでは〇〇が3本、△△が2本と続き、VRや8Kの作品も含まれています。気になる作品は、詳細ページからFANZAの公式情報を確かめてみてください。
- note: 〇〇さん出演の、△△が贈るVR作品です。10月2日の発売で、収録時間は約120分。臨場感のある映像を楽しみたい方にチェックしてほしい一本です。

## うまくいかないとき

- `apply` が断ったとき: 表示された理由（文字数・使えない言葉・一覧にない数字・同じ文の使い回し など）を直して、もう一度実行する
- `list` の `status` が `ready` でないとき: 何もしないで終了する（記事がない週があっても、サイトは壊れない）
- CIが赤いとき: Mergeせず、PRを開いたまま報告する（運営者がClaudeに相談する）
- リポジトリに入れない／PRを作れないとき: 無理に回り道をせず、できなかった理由を報告して終了する。データは壊れていないので、翌週に前の週の分もまとめて書けるよう、`list --week-start 月曜日` で過去の週を指定してやり直してもよい
- 抜けた週の記事は、あとから `list --week-start YYYY-MM-DD`（月曜日）で書ける（1回の実行で1本）
