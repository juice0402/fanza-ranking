# Claude による読み物の記事（毎週月曜の予約タスク）

毎週月曜 0:50（日本時間）の予約タスク（週のまとめ記事と同じ回）で、Claude が**読み物（`/yomimono/`）の記事を1本**書きます。
読み物は、ジャンル・テーマごとの、ブログのような記事です（例: 「AIリマスター版ってなに？」）。検索で「FANZA AIリマスター とは」のような言葉から来てもらうための、サイトの読みものです。

記事の中身は次のとおりです（書いたあとは `site/src/data/yomimono.json` に入り、サイトがページにします）。

- **題（title）**: 40文字まで。**説明文（description）**: 80〜120文字（検索結果に出る文）
- **導入文（lead）**: 2つの段落
- **節（sections）**: 4〜6個。どれも見出し（h）と本文（text。1〜3段落）。1つの節だけ、年ごとの本数のグラフを付けられる（`"chart": "years"`）
- **最初に見るならこの5本（picks）**: ちょうど5本。1本ごとに理由（why。40〜80文字）

本数・年ごとの本数・メーカー・評価などの数字は、**道具（`scripts/claude_yomimono.py`）がサイトの全作品から数えます**（作品タイトルは出しません）。Claude はその数字を、話を支える材料として使います。
1回に書くのは1本だけです。書き直す記事（確かめた日から90日をすぎたもの）があれば、新しいテーマより先に書き直します。

## 手順

週のまとめ記事の手順（`docs/claude-roundups.md`）と同じブランチ・同じPRで進めてよい（リポジトリの用意・CI・公開を待つのが1回で済む）。読み物だけを書くときは、ブランチ名を `claude/yomimono-$(TZ=Asia/Tokyo date +%Y%m%d-%H%M)` にする。

1. 何を書くかを決める: `python3 scripts/claude_yomimono.py themes`（別名 `candidates`）
   - `rewrite` に記事があれば、**先頭の1本を書き直す**（slug はそのまま）
   - 無ければ `builtin`（はじめの4本のテーマ: `hard`・`gensaku`・`ai-remaster`・`vr`）の先頭を、それも無ければ `new`（100本以上のジャンル）から1つを選んで、新しく書く。slug は英小文字・数字・ハイフンの短いローマ字（例: `jukujo`・`hitozuma`）
   - 未成年を連想させるテーマ・無理やりや犯罪を思わせるテーマは、道具が出さない・受け付けない。ほかの言葉で言いかえてテーマにすることもしない
2. 数字を出す: `python3 scripts/claude_yomimono.py list --slug <slug>`（新しいテーマは `--genres ジャンル` か `--keywords 題に入る言葉` も。カンマ区切りで複数）
   - `status` が `too_few`（選べる作品が5本に満たない）なら、ほかのテーマにする
   - `facts`（テーマの数字）と `candidates`（選べる作品。最大30本）が出る。くわしくは下の「list に出るもの」
3. 下の「書き方」に沿って書き、次の形のJSONファイルにする（作業用の置き場に。リポジトリには入れない）
   ```json
   {"<slug>": {"theme": {"genres": [...], "keywords": [...]}, "title": "…", "description": "…", "lead": "段落1\n段落2",
     "sections": [{"h": "見出し", "text": "段落1\n段落2"}, {"h": "…", "text": "…", "chart": "years"}],
     "picks_h": "最初に見るならこの5本", "picks": [{"cid": "…", "why": "…"}]}}
   ```
   - `theme` は list に出た `theme` をそのまま（はじめの4本と、書き直しのときは省いてよい）。`picks_h` は省くと「最初に見るならこの5本」
4. 点検して書き込む: `python3 scripts/claude_yomimono.py apply ファイル.json`（先に `--dry-run` でもよい）
   - 問題があると**何も書き込まれず**、理由が1行ずつ出る。直してもう一度実行する
   - 書き込むと、`written`（はじめて書いた日。書き直しでもそのまま）・`checked`（今日）・`total`（数えた本数）・グラフの節があれば `years` も入る
5. `bash scripts/check.sh` を実行して、最後が「✅ ぜんぶ成功」であることを確認する
6. `git status` で、変わったのが **`site/src/data/yomimono.json` だけ**（週・月のまとめと同じPRなら、`roundups.json`・`monthly.json` も）であることを確認する。ほかのファイルが変わっていたらコミットしない
7. コミット → push → PR（`gh api repos/juice0402/fanza-ranking/pulls ... --jq '.number'`）。題とコミットメッセージは `読み物を追加（Claude）: <記事の題>`（書き直しは `読み物を書き直し（Claude）: <記事の題>`）。週のまとめと同じPRなら、うしろに `＋読み物: <記事の題>`
8. CI を待つ: `python3 scripts/wait_run.py ci $(git rev-parse HEAD)`
   - **`✅` で、PRが変えたのが `yomimono.json` だけ（または、まとめ記事のデータとの組み合わせだけ）なら、Claude が Merge してよい**（CLAUDE.md の守ること1に、この許可が書かれていることを確かめてから。書かれていなければ Merge せず、PRを開いたまま報告する）
   - `❌`・時間切れ・衝突のときは Merge しない。理由を報告する
9. Merge したら `python3 scripts/wait_run.py deploy <Merge のコミット>` で公開を待ち、本番の `https://av-sale-guide.com/yomimono/<slug>/?cb=日時` を WebFetch で見る（prompt は「記事の見出しと導入文の最初の1文だけを答えて」）。見られなかったら「未確認」と書く
10. 報告: 書いた記事（slug・題・新しく書いたか書き直しか）／PR番号／CI の結果／Merge したか／本番で確認できたか

## list に出るもの

`facts`（作品タイトルは入らない。数えた日は `today`）:

| 項目 | 中身 |
|---|---|
| `total`・`released`・`upcoming` | テーマの作品の数（予約も入れる）・発売済み・予約 |
| `excluded` | そのうち、読み物で選べない作品の数（数には入れてよい。選べる作品には入らない） |
| `site_total`・`share` | サイトの全作品の数・その中のテーマの割合（`pct`・`one_in`・`phrase`＝「101本に1本」） |
| `years` | 年ごとの本数 `[{y, n}]`（グラフに使う） |
| `months` | 今日の月までの12か月 `[{m, n, all, pct, one_in, phrase}]`（`all` はその月にサイトが集めた作品の数。月によって大きくちがうので、本数より「N本に1本」で比べる） |
| `makers` | 多い順に5社 `[{name, n, months（出した月の数）, series, label（いちばん多いシリーズ・レーベルと本数）}]` |
| `actresses` | 2本以上に出た人を5人 `[{name, n}]` |
| `minutes` | 収録時間 `known`（分かる本数）・`median`（真ん中の値）・`long`（240分以上）・`long_best`（そのうち総集編）・`best`（総集編。2つのジャンルの合計）・`best_general`（「ベスト・総集編」）・`best_actress`（「女優ベスト・総集編」） |
| `single`・`no_actress` | 1人だけが出ている作品・出演者の無い作品 |
| `reviews` | FANZAのレビュー `reviewed`（レビューのある本数）・`avg`（★の平均）・`site_avg`（サイト全体の平均）・`count`（件数の合計）・`per_work`（1本あたりの件数） |
| `sale` | `now`（いまセール中の本数）・`max_off`（いちばん大きい割引の%） |
| `rank` | 人気の順位 `best`（いちばん上）・`top100`・`top1000`・`ranked` |
| `genres` | いっしょに付いているジャンル（多い順に8つ） |
| `cid_ai`・`classic` | 番号の終わりが `ai` の作品の数・「クラシック」「復刻」の作品の数 |

`candidates`: 選べる作品（発売済み・外す作品ではない）を、人気の順位・★（件数でならす）・セールの点の高い順に30本まで（同じメーカーは3本まで）。
`cid`・`date`・`maker`・`actress`・`minutes`・`genres`・`series`・`rank`・`stars`・`reviews`・`sale`（`{off, end}` か null）。

## 書き方（運営者が決めた決まり）

`apply` が点検するので、違反するとはじかれます。

### 全体

- **数字のレポートではなく、ブログの記事の書き方にする。** 数字は話を支える材料として、1段落に2〜3個まで（4つ以上は `apply` が断る。日付と1〜10の小さな数は数えない）。「2.0%」より「50本に1本」のように、読んで分かる言い方を選ぶ（`phrase`）
- **書き出しは、読む人が目にしている事実から始める**（例: 「最近、FANZAの新作の一覧で【AIリマスター版】という文字をよく見かけるようになりました。」）。「〜と思ったことはありませんか？」のような決まり文句の問いかけは使わない
- 自分の体験・感想（私・筆者・見てみた・使ってみた・思います など）、作り話、直接的な描写は書かない。**作品の題は本文に書かない**（題はカードにだけ出る。どの作品の題からでも10文字以上そのまま写すと `apply` が断る）
- ジャンルの名前に使えない言葉が入っているとき（「淫乱・ハード系」の「淫乱」）は、名前をそのまま書かず、使える部分（「ハード系」）で書く（`apply` が断る）
- ジャンルの説明は、だれでも確かめられる一般的な事実だけにする。総集編のジャンルは「ベスト・総集編」と「女優ベスト・総集編」の2つがある（両方を数える。`minutes.best`）。古い作品には「クラシック」「復刻」が付くことがある
- 長さは、導入文と節の本文の合計で**全角2,000〜3,000文字**（改行は数えない）
- 「です・ます」調。古くなる言い方（今月・今週・今日 など）は使わず、日付で書く。数えた日を書くときは「10月28日の時点で」
- **AIの文章によく出る言い方は使わない**（おすすめ・ぜひ・便利・簡単・安心・ポイント・コツ・しましょう・——）。絵文字・矢印・飾りの記号・URL・マークダウンも入れない（FANZAのレビューの「★」はよい）。「話題」「大人気」「待望」のような確かめられない評価も書かない
- 使ってよい数字は、`facts` の数字（1,234・1234・% のどの書き方でも）・`phrase` の「N本に1本」・となりの年や月との差・選んだ5本の数字（収録時間・順位・★・件数・割引）・日付・1〜10の小さな数・「約」のあとの丸めた数（約1,500本）。ほかの数字は `apply` が断る
- 未成年を連想させるジャンル・無理やりや暴力を思わせるジャンルは、テーマにしない

### 見出しと流れ

見出しは短い問いかけか、言い切りにする。例: 「〇〇ってなに？」「2026年は、もう去年の本数をこえた」「ドラマものと熟女ものが多い」「こんな人に向いています」「選ぶ前に知っておきたいこと」「最初に見るならこの5本」

ふつうの流れ:

1. 導入文（2段落）: 目にしている事実から入り、このサイトでの本数・割合と、記事で何を見ていくかを書く
2. 「〇〇ってなに？」: テーマの一般的な説明（確かめられる事実だけ）
3. 数字で見る動き: 年ごとの本数（この節に `"chart": "years"`）と、月ごとの割合
4. 多いメーカー・出演者: 本数と、出し方（何か月に分けて出したか・シリーズ）
5. 「こんな人に向いています」: 収録時間・ジャンル・評価の数字から
6. 「選ぶ前に知っておきたいこと」: 総集編の見分け方など。サイトの道具に案内する（作品ページのサンプル動画・レビューの件数・お気に入り）
7. 最初に見る5本（`picks`）

### 最初に見る5本（picks）

- `candidates` の `cid` から、ちょうど5本。メーカー・収録時間・発売の年がばらけるように選ぶ
- 理由（`why`）は40〜80文字。その作品の数字と作品の情報（メーカー・出演者・収録時間・ジャンル・順位・★・セール）だけで書き、**どんな人に向くかの1文を入れる**（「〜な人に向いています」）。体験・感想は書かない。同じ文を使い回さない

### 書き方の例（AIリマスター版の記事の、数字の節の1段落。数字は例）

> 発売された年ごとに数えると、2022年は4本、2023年は3本と、はじめはごくわずかでした。それが2025年には54本になり、2026年は10月28日の時点で71本と、すでに去年をこえています。新作の一覧で目につくようになったのは、ここ1年ほどのことだと分かります。

## うまくいかないとき

- `apply` の理由を読んで直す。数字の理由（facts にない数字）は、`facts` にある数字に言いかえるか、数字を使わずに書く
- 何度直しても通らないときは、PRを作らずに、理由を報告して終了する（サイトは前のまま）
