# Claude による読み物の記事（毎週月曜の予約タスク）

毎週月曜 0:50（日本時間）の予約タスク（週のまとめ記事と同じ回）で、Claude が**読み物（`/yomimono/`）の記事を1本**書きます。
読み物は、ジャンル・テーマごとの「**調べてまとめる記事**」です（例: 「FANZAのドラマ作品ってなに？話の型とメーカーで選ぶ」）。検索で「FANZA ドラマ とは」のような言葉から来た人の問いに、調べて確かめた情報で答えます。

2026-11-04 に書き方を変えました（#220。運営者「まだまだ数値報告みたいで、ブログ記事や情報記事みたいな感じになってない」「今あるデータだけでは書かないで！必ず情報を調べて、情報がまとまった記事にしてね」）。
**芯は WebSearch で調べて確かめた情報**です。サイトの数字（本数・割合・順位・レビュー・セール）は、その話を支える材料として少しだけ使います。10/28 の見本（プロジェクトの claude/fanza-yomimono-sample.md）と「1段落に数字3つまで」だけの決まりは古く、この文書が優先です。

記事の中身は次のとおりです（書いたあとは `site/src/data/yomimono.json` に入り、サイトがページにします）。

- **題（title）**: 40文字まで。**説明文（description）**: 80〜120文字（検索結果に出る文）
- **導入文（lead）**: 2つの段落
- **節（sections）**: 4〜6個。どれも見出し（h）と本文（text。1〜3段落）。1つの節だけ、年ごとの本数のグラフを付けられる（`"chart": "years"`）
- **最初に見るならこの5本（picks）**: ちょうど5本。1本ごとに理由（why。40〜100文字）
- **調べた資料（sources）**: 2つ以上。`[{"title": ページの題, "site": サイトの名前, "url": URL, "checked": 開いて確かめた日}]`。記事ページのいちばん下（5本のあと）に、題とサイトの名前のリンクで小さく出ます

数字は**道具（`scripts/claude_yomimono.py`）がサイトの全作品から数えます**（作品タイトルは出しません）。
1回に書くのは1本だけです。書き直す記事（確かめた日から90日をすぎたもの）があれば、新しいテーマより先に書き直します。

## 手順

週のまとめ記事の手順（`docs/claude-roundups.md`）と同じブランチ・同じPRで進めてよい（リポジトリの用意・CI・公開を待つのが1回で済む）。読み物だけを書くときは、ブランチ名を `claude/yomimono-$(TZ=Asia/Tokyo date +%Y%m%d-%H%M)` にする。

1. 何を書くかを決める: `python3 scripts/claude_yomimono.py themes`（別名 `candidates`）
   - `rewrite` に記事があれば、**先頭の1本を書き直す**（slug はそのまま）
   - 無ければ `builtin`（はじめの4本のテーマ: `hard`・`gensaku`・`ai-remaster`・`vr`）の先頭を、それも無ければ `new`（100本以上のジャンル）から1つを選んで、新しく書く。slug は英小文字・数字・ハイフンの短いローマ字（例: `jukujo`・`hitozuma`）
   - 未成年を連想させるテーマ・無理やりや犯罪を思わせるテーマは、道具が出さない・受け付けない。ほかの言葉で言いかえてテーマにすることもしない
2. 数字を出す: `python3 scripts/claude_yomimono.py list --slug <slug>`（新しいテーマは `--genres ジャンル` か `--keywords 題に入る言葉` も。カンマ区切りで複数）
   - `status` が `too_few`（選べる作品が5本に満たない）なら、ほかのテーマにする
   - `facts`（テーマの数字）と `candidates`（選べる作品。最大30本）が出る。くわしくは下の「list に出るもの」
3. 下の「調べ方」で調べる（WebSearch → 結果に出たページを開いて確かめる。開いた URL と日を控えておく）
4. 下の「書き方」に沿って書き、次の形のJSONファイルにする（作業用の置き場に。リポジトリには入れない）
   ```json
   {"<slug>": {"theme": {"genres": [...], "keywords": [...]}, "title": "…", "description": "…", "lead": "段落1\n段落2",
     "sections": [{"h": "見出し", "text": "段落1\n段落2"}, {"h": "…", "text": "…", "chart": "years"}],
     "picks_h": "最初に見るならこの5本", "picks": [{"cid": "…", "why": "…"}],
     "sources": [{"title": "ページの題", "site": "サイトの名前", "url": "https://…", "checked": "YYYY-MM-DD"}]}}
   ```
   - `theme` は list に出た `theme` をそのまま（はじめの4本と、書き直しのときは省いてよい）。`picks_h` は省くと「最初に見るならこの5本」
5. 点検して書き込む: `python3 scripts/claude_yomimono.py apply ファイル.json`（先に `--dry-run` でもよい）
   - 問題があると**何も書き込まれず**、理由が1行ずつ出る。直してもう一度実行する
   - 書き込むと、`written`（はじめて書いた日。書き直しでもそのまま）・`checked`（今日）・`total`（数えた本数）・グラフの節があれば `years` も入る
6. `bash scripts/check.sh` を実行して、最後が「✅ ぜんぶ成功」であることを確認する
7. `git status` で、変わったのが **`site/src/data/yomimono.json` だけ**（週・月のまとめと同じPRなら、`roundups.json`・`monthly.json` も）であることを確認する。ほかのファイルが変わっていたらコミットしない
8. コミット → push → PR（`gh api repos/juice0402/fanza-ranking/pulls ... --jq '.number'`）。題とコミットメッセージは `読み物を追加（Claude）: <記事の題>`（書き直しは `読み物を書き直し（Claude）: <記事の題>`）。週のまとめと同じPRなら、うしろに `＋読み物: <記事の題>`
9. CI を待つ: `python3 scripts/wait_run.py ci $(git rev-parse HEAD)`
   - **`✅` で、PRが変えたのが `yomimono.json` だけ（または、まとめ記事のデータとの組み合わせだけ）なら、Claude が Merge してよい**（CLAUDE.md の守ること1に、この許可が書かれていることを確かめてから。書かれていなければ Merge せず、PRを開いたまま報告する）
   - `❌`・時間切れ・衝突のときは Merge しない。理由を報告する
10. Merge したら `python3 scripts/wait_run.py deploy <Merge のコミット>` で公開を待ち、本番の `https://av-sale-guide.com/yomimono/<slug>/?cb=日時` を WebFetch で見る（prompt は「記事の見出しと導入文の最初の1文だけを答えて」）。見られなかったら「未確認」と書く
11. 報告: 書いた記事（slug・題・新しく書いたか書き直しか）／PR番号／CI の結果／Merge したか／本番で確認できたか

## 調べ方

- テーマ・メーカー・レーベル・監督・シリーズについて WebSearch で調べ、**結果に出たページを開いて確かめる**。自分で URL を作らない・思い出した URL を開かない（開けないページは使わない）
- 使ってよい資料: FANZA の公式のページ（ジャンル・特集・お知らせ・ヘルプ）、メーカー・レーベルの公式サイトとお知らせ、ニュースの記事、事典に出る事実（設立の年など。**2つ以上の資料で一致したものだけ**）
- 使わない資料: ブログ・まとめ・ほかのレビューのサイト・掲示板・SNS のうわさ。女優の私生活・うわさは書かない
- 資料どうしで言うことがちがうときは、公式のほうを使う。公式がなければ書かない。確かめられないことは書かない
- 資料の文は写さず、自分の言葉で短く書く。資料の数字（値段・本数など）は `apply` が facts にない数字として断るので、数字を使わずに書く（年・月・日はよい）
- 開いて使ったページを `sources` に入れる（2つ以上。題はページの題のまま、`checked` は開いた日）。このサイトのページは資料にしない。AIの文章によく出る言い方・使えない言葉が題に入っているページは、題に使えないので別の資料にする
- 調べ物の目安: テーマのジャンルがどんな作品に付くか、作品の多いメーカーとレーベルの成り立ちと作風、シリーズ・監督の特色、原作や機器（VR・画質）・総集編のような選ぶ前に知っておきたいこと
- 確かめられた情報が少なくて節が書けないときは、その節を数字で埋めずに外す（節は4つ以上あればよい）

## list に出るもの

`facts`（作品タイトルは入らない。数えた日は `today`）:

| 項目 | 中身 |
|---|---|
| `total`・`released`・`upcoming` | テーマの作品の数（予約も入れる）・発売済み・予約 |
| `excluded` | そのうち、読み物で選べない作品の数（数には入れてよい。選べる作品には入らない） |
| `site_total`・`share` | サイトの全作品の数・その中のテーマの割合（`pct`・`one_in`・`phrase`＝「101本に1本」） |
| `years` | 年ごとの本数 `[{y, n}]`（グラフに使う） |
| `months` | 今日の月までの12か月 `[{m, n, all, pct, one_in, phrase}]`（`all` はその月にサイトが集めた作品の数。月によって大きくちがうので、本数より「N本に1本」で比べる） |
| `makers` | 多い順に5社 `[{name, n, months（出した月の数）, series, label（いちばん多いシリーズ・レーベルと本数）}]` |
| `actresses` | 2本以上に出た人を5人 `[{name, n}]` |
| `minutes` | 収録時間 `known`（分かる本数）・`median`（真ん中の値）・`long`（240分以上）・`long_best`（そのうち総集編）・`best`（総集編。2つのジャンルの合計）・`best_general`（「ベスト・総集編」）・`best_actress`（「女優ベスト・総集編」） |
| `single`・`no_actress` | 1人だけが出ている作品・出演者の無い作品 |
| `reviews` | FANZAのレビュー `reviewed`（レビューのある本数）・`avg`（★の平均）・`site_avg`（サイト全体の平均）・`count`（件数の合計）・`per_work`（1本あたりの件数） |
| `sale` | `now`（いまセール中の本数）・`max_off`（いちばん大きい割引の%） |
| `rank` | 人気の順位 `best`（いちばん上）・`top100`・`top1000`・`ranked` |
| `genres` | いっしょに付いているジャンル（多い順に8つ） |
| `cid_ai`・`classic` | 番号の終わりが `ai` の作品の数・「クラシック」「復刻」の作品の数 |

`candidates`: 選べる作品（発売済み・外す作品ではない）を、人気の順位・★（件数でならす）・セールの点の高い順に30本まで（同じメーカーは3本まで）。
`cid`・`date`・`maker`・`actress`・`minutes`・`genres`・`series`・`rank`・`stars`・`reviews`・`sale`（`{off, end}` か null）。

## 書き方（運営者が決めた決まり）

`apply` が点検するので、違反するとはじかれます。

### 全体

- **数字のレポートではなく、調べた情報がまとまった記事にする。** 1本に、調べた情報を芯にした節を3つ以上。サイトの数字は、その話を支える材料として使う
- **数字は、導入文と節の本文の合計で10個まで**（表・グラフ・5本のカードの外。日付と1〜10の小さな数は数えない。11個以上は `apply` が断る）。1つの段落に数字を3つより多く書かない（`apply` が断る）。「2.0%」より「50本に1本」のように、読んで分かる言い方を選ぶ（`phrase`）
- **書き出しは、読む人が目にしている事実から始める**（例: 「FANZAの作品ページを開くと、ジャンルの欄に「ドラマ」と書かれた作品がよく並んでいます。」）。「〜と思ったことはありませんか？」のような決まり文句の問いかけは使わない
- 自分の体験・感想（私・筆者・見てみた・使ってみた・思います など）、作り話、直接的な描写は書かない。**作品の題は本文に書かない**（題はカードにだけ出る。どの作品の題からでも10文字以上そのまま写すと `apply` が断る）
- ジャンルの名前に使えない言葉が入っているとき（「淫乱・ハード系」の「淫乱」）は、名前をそのまま書かず、使える部分（「ハード系」）で書く（`apply` が断る）
- 長さは、導入文と節の本文の合計で**全角2,500〜4,000文字**（改行は数えない）。水増ししない（同じことを言いかえない・前置きやまとめの段落を書かない）
- 「です・ます」調。古くなる言い方（今月・今週・今日 など）は使わず、日付で書く。数えた日を書くときは「11月4日の時点で」
- **AIの文章によく出る言い方は使わない**（おすすめ・ぜひ・便利・簡単・安心・ポイント・コツ・しましょう・——）。絵文字・矢印・飾りの記号・URL・マークダウンも入れない（FANZAのレビューの「★」はよい）。「話題」「大人気」「待望」のような確かめられない評価も書かない
- 本文に使ってよい数字は、`facts` の数字（1,234・1234・% のどの書き方でも）・`phrase` の「N本に1本」・となりの年や月との差・選んだ5本の数字・日付・1〜10の小さな数・「約」のあとの丸めた数（約1,500本）。ほかの数字は `apply` が断る
- 未成年を連想させるテーマ・無理やりや暴力を思わせるテーマにしない（調べた資料にそういう作風が書かれているメーカーは、記事で取り上げない）

### 見出しと流れ

見出しは、読む人の問いか、中身の言葉にする。**数字で言い切る見出しにしない**（見出しに数字を入れると `apply` が断る。「100位以内に25本が入っている」のような見出しは作らない）。見出しを上から読むだけで、問いと答えの筋が分かるようにする。

1. 導入文（2段落）: 読む人が目にしている事実から入り、この記事で分かることを書く。数字は1つまで
2. 「〇〇ってなに？」: しくみ・成り立ち・ほかとのちがいを、調べた情報で
3. 「どんな種類がある？」: 2〜4つの型（設定・作り方・メーカーの色など）を、調べた情報とサイトのデータ（いっしょに付くジャンル・シリーズ・レーベル）で紹介し、型ごとに「こんな人に向いています」を1文
4. 「どこから見ればいい？」: メーカー・レーベル・監督の特色を調べた情報で。サイトの本数は1〜2個だけ
5. 「数字で見る〇〇」（あってもなくてもよい）: サイトの数字はできるだけこの節にまとめる。年ごとのグラフ（`"chart": "years"`）はこの節に
6. 「選ぶ前に知っておきたいこと」: 総集編・画質・機器など、調べた情報で。サイトの道具（作品ページのサンプル動画・レビューの件数・お気に入り）にも1回つなぐ
7. 最初に見るならこの5本（`picks`）: 3の型がばらけるように選ぶ

### 最初に見る5本（picks）

- `candidates` の `cid` から、ちょうど5本。「どんな種類がある？」の型がばらけるように選ぶ（メーカー・発売の年もなるべくばらけるように）
- 理由（`why`）は40〜100文字。どんな作品か（ジャンル・シリーズ・監督・設定。作品の説明文がデータや API にあれば言いかえて使ってよい）と、**どんな人に向くかの1文**（「〜な人に向いています」）。体験・感想は書かない。同じ文を使い回さない
- **順位・★・件数・割引の数字は書かない**（カードに出ている。書くと `apply` が断る）。書いてよい数字は、その作品の収録時間と年だけ

### 書き方の例（ドラマの記事の「どんな種類がある？」の1段落）

> 次が、会社を舞台にした話です。上司と部下、同僚、出張先といった場面から話が動き、OLや部下・同僚のジャンルが付いた作品が目立ちます。エスワン ナンバーワンスタイルには、出張先の相部屋を舞台にしたシリーズもあります。日常の延長にある設定で、登場人物の関係を追っていきたい人に向いています。

## うまくいかないとき

- `apply` の理由を読んで直す。数字が多すぎるときは、数字を「数字で見る」の節に寄せるか、調べた情報で書きかえる。数字の理由（facts にない数字）は、`facts` にある数字に言いかえるか、数字を使わずに書く
- 何度直しても通らないときは、PRを作らずに、理由を報告して終了する（サイトは前のまま）
